## 1. 项目概述

Pi Web 读取本地 pi 会话文件（`~/.pi/agent/sessions/**/*.jsonl`），在浏览器式的工作台中提供：

- **会话浏览与恢复**：按项目分组浏览历史会话，无需翻终端历史
- **实时对话**：在网页中直接驱动 pi 代理，SSE 流式渲染
- **分支操作**：会话内分支（同一文件内多路探索）与会话分叉（生成独立新文件）
- **Git 集成**：工作区状态、逐文件 diff、worktree 切换/创建/删除
- **文件工作台**：侧栏文件树 + 右侧预览（源码、diff、图片、音频、PDF、DOCX）
- **配置管理**：模型配置（models.json）、OAuth/API Key 登录、插件与技能管理
- **富文本渲染**：Markdown + GFM + KaTeX 数学公式 + Mermaid 图表 + 代码高亮；会话可导出为独立 HTML
- **状态可视化**：上下文用量、会话成本（按模型定价计算）、压缩状态、系统提示词

## 3. 运行方式

### 桌面应用（推荐）

从 GitHub Releases 下载安装包，自带运行时，**无需安装 Node.js**。内置服务器监听 `127.0.0.1:30141`。

### 源码运行

```bash
npm install
npm run build
npm start            # http://127.0.0.1:30141
npm run desktop      # 从源码启动 Electron 窗口（需先 build）
```

### 开发模式

```bash
npm run dev          # 127.0.0.1:30141（局域网调试用 dev:lan）
```

### CLI 选项

```bash
pi-web --port 8080 --hostname 0.0.0.0 --no-open
PORT=8080 PI_WEB_NO_OPEN=1 pi-web
```

> ⚠️ **安全警告**：应用无鉴权且能调用高权限代理，切勿暴露到公网；非回环绑定仅限可信网络。

## 4. 整体架构

```
浏览器                      Next.js 服务器                  AgentSession（进程内）
  │                             │                                │
  ├─ GET /api/sessions ─────────▶ 直读 ~/.pi/agent/sessions/      │
  ├─ GET /api/sessions/[id] ────▶ 解析 .jsonl（只读，不建会话）    │
  ├─ GET /api/agent/running/events ─▶ 运行中会话 id 的 SSE        │
  │                             │                                │
  ├─ 发送消息 ──────────────────▶ POST /api/agent/[id]           │
  │                             │   startRpcSession() ──────────▶│ createAgentSession()
  │                             │   session.send(cmd) ──────────▶│ session.prompt()
  │                             │                                │
  ├─ SSE 连接 ──────────────────▶ GET /api/agent/[id]/events     │
  │                             │   session.onEvent() ◀─────────│ session.subscribe()
  │◀── data: {...} ─────────────│                                │
```

**两条截然不同的读取路径：**

| 操作 | 路径 | 是否创建 AgentSession |
|---|---|---|
| 浏览/打开历史会话 | `lib/session-reader.ts` 直接解析 `.jsonl` | 否 |
| 发送消息/交互 | `lib/rpc-manager.ts` 的 `startRpcSession()` | 是（进程内常驻） |

- 外部链接一律交给系统浏览器
- 服务器输出写入 `userData/logs/pi-web-server.log`，异常退出弹错误对话框
- 窗口全关即退出并杀掉服务器子进程

## 8. 核心数据流

### 8.1 发送一条消息

1. `ChatInput` → `useAgentSession.sendMessage()` → `POST /api/agent/[id]` `{type:"prompt",...}`
2. 路由从 `globalThis.__piSessions` 取包装器，不存在则 `startRpcSession()` 创建
3. `AgentSession.prompt()` 开始流式执行
4. 前端同时挂 `GET /api/agent/[id]/events` SSE，事件经 `normalizeToolCalls()` 归一化后渲染
5. 运行期间周期性 `GET /api/agent/[id]` 对账 + `visibilitychange`/`online` 触发补偿，防止后台标签页漏掉 `agent_end`
6. `onAgentEnd` 播放完成提示音；运行 id 单调递增，迟到事件被丢弃

### 8.2 两种"分支"——勿混淆

| | Fork（分叉） | 会话内分支 |
|---|---|---|
| 入口 | 用户消息上的 Fork 按钮 | Continue / BranchNavigator |
| 机制 | `AgentSession.fork()` 生成**新的 .jsonl 文件** | `navigate_tree` 在**同一文件内**切换叶子 |
| 侧栏表现 | 通过 header `parentSession` 显示为子会话 | 同一会话内多条同 `parentId` 的条目 |
| 切换 | 直接打开新会话 | `/api/sessions/[id]/context?leafId=` |

### 8.3 页面刷新中途恢复

`ChatWindow` 挂载时 `GET /api/agent/[id]`：若 `isStreaming === true` 自动重连 SSE，并同步 `thinkingLevel` / `isCompacting`。

## 9. 会话文件格式

位置：`~/.pi/agent/sessions/<encoded-cwd>/<timestamp>_<uuid>.jsonl`（可用 `PI_CODING_AGENT_DIR` 改根目录）

```jsonl
{"type":"session","version":3,"id":"<uuid>","timestamp":"...","cwd":"/path","parentSession":"/abs/parent.jsonl"}
{"type":"model_change","id":"<8hex>","parentId":null,"provider":"zenmux","modelId":"claude-sonnet-4-6","timestamp":"..."}
{"type":"message","id":"<8hex>","parentId":"<8hex>","message":{"role":"user","content":"..."}}
{"type":"message","id":"<8hex>","parentId":"<8hex>","message":{"role":"assistant","content":[...]}}
{"type":"message","id":"<8hex>","parentId":"<8hex>","message":{"role":"toolResult","toolCallId":"...","content":[...]}}
{"type":"compaction","id":"<8hex>","parentId":"<8hex>","summary":"...","firstKeptEntryId":"<8hex>","tokensBefore":N}
{"type":"session_info","id":"...","parentId":"...","name":"user-defined name"}
```

要点：

- 条目以 `id`/`parentId` 构成**树**（非线性），支持同层多分支
- `SessionContext.entryIds[]` 与 `messages[]` 平行，用于 fork / navigate_tree
- `parentSession` 仅是展示元数据，对聊天内容无影响——整个文件可被安全重写（删除会话时级联重挂子会话即利用此特性）

## 10. 关键设计要点与陷阱

1. **`globalThis` 注册表**：`__piSessions` / `__piStartLocks` / `__piLoginCallbacks` 挂全局对象以抗 Next.js 热重载；模块级 Map 会在热重载后丢失。
2. **Fork 后必须立即销毁包装器**：`AgentSession.fork()` 会**原地改写** wrapper 内部状态（`sessionId` 变为新会话 id）。`send("fork")` 捕获新 id 后立即 `this.destroy()`，否则后续请求拿到的是已分叉状态，分叉链会腐坏。
3. **工具调用字段归一化**：pi 存储 `{id,name,arguments}`，UI 类型用 `{toolCallId,toolName,input}`。`normalizeToolCalls()` 在文件加载（`session-reader.ts`）和流式事件（`ChatWindow`）两处都必须调用。
4. **工具完全禁用时清空系统提示词**：`toolNames = []` 时传空工具白名单并在启动后强制 `agent.state.systemPrompt = ""`。
5. **压缩事件双兼容**：新版 pi 发 `compaction_start/end`，旧版发 `auto_compaction_start/end`，`handleAgentEvent` 两组都收。
6. **手动压缩是阻塞 POST**：按钮在响应返回前保持禁用。
7. **worktree 归属**：会话 cwd 若指向已删除的 worktree，会被归并回主项目而不是变成幽灵项目行。
8. **开发期禁止 `next build`**：会污染 `.next/` 导致 dev server 异常。
9. **导出的 HTML 打补丁**：把递归树渲染改为迭代版本，防止超深线性会话在浏览器爆栈。

## 11. 安全模型

| 机制 | 位置 | 说明 |
|---|---|---|
| 文件访问白名单 | `lib/file-access.ts` | `/api/files`、`/api/worktrees` 共用；允许的根 = 会话 cwd + 项目根 + `~/pi-cwd-*` + `allowFileRoot()` 显式登记的根。**不是通用文件浏览器** |
| 跨源防护 | `proxy.ts` + `lib/request-security.ts` | Next.js 中间件拦截 `/api/*`，拒绝跨源请求（403） |
| API Key 保密 | `/api/auth/api-key/*` | 状态接口绝不返回明文 Key |
| 无应用层鉴权 | 全局 | 默认仅绑 `127.0.0.1`；`--hostname 0.0.0.0` 时 CLI 打印警告，仅限可信网络 |
| 代理 | `lib/http-dispatcher.ts` + `instrumentation.ts` | 服务端模型/API 请求走 `HTTP(S)_PROXY` / `NO_PROXY` |

## 12. 权限模式

`config/modes.json`（参照 Claude Code 权限模式标准），通过 `/api/modes` 下发：

| 模式 | auto（免确认） | ask（注入约束） | deny（不注入） | 适用 |
|---|---|---|---|---|
| `manual` | read/grep/find/ls | edit/write/bash | — | 入门、敏感操作 |
| `acceptEdits` | + edit/write | bash | — | 日常迭代 |
| `plan` | read/grep/find/ls | — | edit/write/bash | 只读探索 |
| `auto`（默认） | 全部 | — | — | 长期任务 |

实现说明：pi SDK 无原生确认粒度，`ask` 通过 system prompt 注入约束模拟；实际 `set_tools` = auto ∪ ask。

## 14. 构建与发布

### npm 包

```bash
npm run release    # version patch → build → publish（files 仅含 bin/dist）
```

### 桌面安装包

生产构建**不再依赖 Next.js 运行时**（阶段 2）：`npm run build` 执行 `bin/build-all.js`——静态导出客户端 + esbuild 打包服务器 + nft 追踪依赖 + 资产镜像，产出自包含的 `dist/`（约 42MB）：

```bash
npm run build          # bin/build-all.js：静态导出 + esbuild + nft → dist/
npm run desktop        # 本地冒烟测试 Electron 壳
npm run desktop:build  # 产出 Windows NSIS + portable 到 release/
npm run desktop:pack   # 免安装目录（--dir）
```

- electron-builder 配置内嵌于 `package.json` 的 `build` 字段：`asar: false`，产物名含版本号
- 发布由 GitHub Actions 完成：手动触发 `.github/workflows/build-desktop.yml`，自动打上 `*-build.<timestamp>` 版本号、构建并发布 Release

### 桌面故障排查

启动失败时查看错误对话框中提示的日志路径（`userData/logs/pi-web-server.log`）。
